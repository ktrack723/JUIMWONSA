# 설계 원장 — 요소 하나하나의 의의와, 수치냐 텍스트냐

이 문서는 두 질문에 답한다.

1. **이 게임의 각 시스템·요소는 왜 존재하는가.**
2. **각 파라미터는 단순 수치가 나은가, 텍스트로 두고 LLM에게 맡기는 게 나은가.**

그리고 계기판 상시 노출(2026-08 전환)이 무엇을 바꿨고 무엇을 안 바꿨는지를 못박는다.

---

## 0. 한 문장 원칙

> **숫자는 코드가 들고, 말은 LLM이 쓴다. LLM은 방향만 고르고, 폭은 코드가 정한다.**
> **화면에 보여주는 것과 프롬프트에 넣는 것은 별개의 결정이다.**

전신(연애조작단 2077)에서 물려받은 원칙이고, 이 저장소의 테스트가 지키는 것이 바로 이것이다.
스칼라를 LLM에 맡기면 전부 무난한 가운데로 수렴한다 — 등급을 맡겼더니 전원이 B급이 됐고,
이름을 맡겼더니 부대가 통째로 「김민준」이 됐다. 반대로 말을 코드에 맡기면 게임이 죽는다.

## 1. 수치 vs 텍스트 — 판정 기준

어떤 값을 놓고 고민할 때 묻는 순서:

| # | 질문 | 예 → | 아니오 → |
|---|---|---|---|
| 1 | 밸런싱·테스트·저장이 필요한가? | **수치(코드)** 가 원본 | 텍스트 후보 |
| 2 | 그 값이 사람 눈에 어떻게 보여야 하는가? | 화면에 숫자/게이지 그대로 | 화면에도 텍스트 |
| 3 | LLM이 그 값을 알아야 하는가? | **밴드(5단계 라벨)로 낮춰서만** | 아예 안 준다 |
| 4 | LLM이 그 값을 움직여야 하는가? | **방향(up/down/same)만** 받고 폭은 코드 | 코드만 움직인다 |

즉 「수치냐 텍스트냐」는 하나의 답이 아니라 **세 겹의 답**이다:
저장은 수치, 화면은 수치(이제), 프롬프트는 텍스트(밴드). 원본은 언제나 하나(코드)다.

- **원수치를 프롬프트에 주면**: 모형이 숫자를 되뇌고("행복도가 3이라..."), 판정이 자기참조가
  되고("이미 높으니 same"), 몰입이 깨진다. 그래서 빌더에 숫자가 오면 그 자리에서 죽는 가드가 있다.
- **텍스트를 원본으로 삼으면**: 드리프트·확률·저장·회귀 테스트가 전부 불가능해진다.
  "요즘 분위기가 좀 그렇다"에는 +1을 할 수 없다.

## 2. 계기판 상시 노출 — 무엇이 바뀌었나

원래 설계는 「파라미터는 숨기고 브리핑의 증상을 읽는 눈이 실력」이었다. 전환 후:

- **정보 게임 → 관리 게임.** 숨은 값 추리가 아니라, 다 보이는 다섯 바늘과 열여섯 개의 멘탈을
  유한한 개입(전부 평판 −1)으로 어디부터 돌보느냐가 게임이 됐다. 저울은 그대로다 —
  가라⇄사고위험, 갈등⇄잔사고/대형사고, 개입⇄평판 — 이제 그 저울이 눈에 보일 뿐이다.
- **노출은 화면의 일, 차단은 프롬프트의 일.** 계기판이 생겨도 LLM은 여전히 밴드까지만 본다.
  수치 누출 테스트는 한 글자도 안 바뀌었다. 병사도 브리핑도 "행복도 4"라고 말하지 않는다.
- **면담의 의의가 바뀌었다.** 정보 채널로서의 면담은 계기판이 대체했다. 남은 것이 진짜 면담이다 —
  주임원사의 실제 업무(사고예방·병 고충 파악)답게, **사람을 붙잡는 상담**. 멘탈 +1.
- **불시점검의 의의가 바뀌었다.** 「밴드를 눈으로 본다」는 죽었다. 대신 파라미터를 직접 미는
  유일한 결정적 레버(가라 −1 · 행복 −1)가 됐다 — 공지(LLM 방향 판정)와 달리 확정이다.
  점검 소견 텍스트는 남는다: 장소-대응표는 이제 장면의 재료다.
- **브리핑의 의의가 바뀌었다.** 유일한 정보 채널 → **숫자를 사람으로 번역하는 서사 채널.**
  "행복도 low"가 "3생활관이 요즘 이상하게 조용합니다"로 도착한다. 게이지와 산문이 한 이야기를 한다.

## 3. 요소별 원장

표기: 저장 = 코드가 드는 원본 / 화면 = 플레이어가 보는 것 / LLM = 프롬프트에 실리는 것.

### 3.1 부대 파라미터 다섯

| 파라미터 | 의의 | 저장 | 화면 | LLM |
|---|---|---|---|---|
| 일과 난이도 | 부대 선택의 무게. 주임원사가 **못 건드리는** 유일한 축 — 달력(계절·주말)만 만진다. 플레이어에게 「통제 밖」이 있어야 통제 안이 값지다 | static+보정 | 게이지(오늘 실효치) | 밴드 |
| 가라 | 핵심 딜레마. 높으면 편하고(행복↑) 낮으면 FM인데, 난이도·지능과 곱해져 사고를 만든다. 정답이 상황마다 다른 축 | 0~10 | 게이지 | 밴드 |
| 행복도 | 분위기. 갈등을 누르고 멘탈을 띄우는 이차 효과의 허브 — 직접 만질 수 없고 가라·난이도·사건을 통해서만 움직인다 | 0~10 | 게이지 | 밴드 |
| 갈등·부조리 | 이 게임의 시한폭탄. 적당하면 잔사고를 누르지만 8부터 탈영·자해의 문을 연다. 「눌러 놓은 게 터질 땐 크게 터진다」 | 0~10 | 게이지(8에 위험 눈금) | 밴드 |
| 평판 | 개입의 화폐. LLM이 절대 못 만진다 — 개입 횟수가 곧 평판. 낮으면 지침 이행률·상담 수용도가 떨어져 모든 레버가 무뎌진다 | 0~10 | 게이지 | 등급 라벨(이행률·솔직도) |

### 3.2 병사별 멘탈 (신설)

| 항목 | 내용 |
|---|---|
| 의의 | 부대 축(갈등≥8)과 별개로 **한 사람이 무너지는 것**도 대형사고를 연다. 큰 사고가 통계가 아니라 얼굴이 되고, 상담이 정확히 그 얼굴을 향한다 |
| 저장 | 0~10 **저장한다** — 계급(전입일에서 계산)과 달리 살아온 결과라서다. 사고로 카운터가 리셋돼도 남는다 |
| 움직임 | 전부 코드: 전입 굴림(인성 하위는 낮게) · 밤마다 부대 분위기가 쓸어감(행복≥8 +1 / 행복≤3 −1 / 갈등≥7 −1, 하루 한 걸음) · 사건 연루 −1(확전 시 −2) · 상담 +1 |
| 화면 | 명부에 미니 게이지 + 숫자, 2 이하는 깜빡임. 상담 목록은 멘탈 낮은 순 |
| LLM | `spirit: low` 밴드만 — 면담(그 병사의 태도)과 사건 장면(연루자 묘사)에 실린다 |
| 왜 개인 스탯 금지 원칙에 안 걸리나 | 기획서가 금지한 것은 「병사별 호감도류 스칼라 증식」이다. 멘탈은 축 하나고, 대형사고 확률·연루 가중·상담이라는 세 기계에 물려 있다 — 장식 스탯이 아니라 두 번째 사고 경로다 |

### 3.3 병사의 나머지

| 요소 | 의의 | 결정 |
|---|---|---|
| 등급(폐급~에이스)·인성 | LLM이 쓰면 전원 B급으로 수렴 → 코드 가중 추첨(지능↑=에이스↑, 마초↑=하위↑). LLM은 굴려진 등급에 **맞는 인물**만 쓴다 | 수치 굴림 → 한글 라벨 |
| 이름 | 부대의 결 그 자체(해병문학 작명 vs 명문대생). LLM에 맡기면 결이 사라진다 | 코드 음절 통 |
| 군번 | 식별자. 실제 형식(연도 2자리+8자리) | 코드 채번 |
| 계급·기수 | 서열 — 누가 누구에게 말을 놓는가. **저장 안 함**: 전입일에서 계산하므로 게임 중에 진급한다 | 계산값 → 화면 숫자·프롬프트 문자열 |
| sheet(인물 본문) | 유일하게 LLM이 원본인 데이터. 성격·말버릇은 수치화하는 순간 죽는다. 한 번 쓰고 영원히 캐시(🟫) | **텍스트** |

### 3.4 하루의 루프

| 요소 | 의의 | 결정 |
|---|---|---|
| 날짜·계절·주말 | 현실 달력 그대로 — 완주가 정확히 「현실의 오늘」에 닿는 맛. 계절 보정과 주말 무일과는 코드 | 수치(날짜 연산) |
| 슬롯 아홉 | 실제 병영 일과표의 압축. 사고 롤의 단위이자 무대 연출의 박자 | static 표 |
| 사고 롤 | 게임의 심장 박동. LLM 없음 — 확률에 LLM이 끼면 밸런싱이 불가능하다 | 수치 공식 |
| 사건 풀 | 후보·심각도·장소는 코드 풀에서. LLM은 **장면만** 쓴다 — 풀 밖 창작을 열면 게임이 사건 종류를 통제 못 한다 | static 표 + 텍스트 장면 |
| 확전 판정(E-3) | 사건→사고의 문지방. 지침 원문을 못 보는 것이 규칙의 핵심 — 보면 지시의 영리함을 채점한다. 출력은 enum 넷뿐 | LLM 방향 → 코드 폭 |
| 무사고 카운터 | 승리 조건. 순수 코드, 어떤 프롬프트에도 안 실린다(메타 정보) | 수치 |

### 3.5 개입 셋 (전부 평판 −1)

| 레버 | 의의 | 기계 |
|---|---|---|
| 면담(상담) | 멘탈이라는 두 번째 사고 경로의 **해독제**. 텍스트 왕복은 채점되지 않는다 — 프롬프팅이지 시험이 아니다 | 멘탈 +1(코드 확정) + LLM 대사 |
| 군기 점검 | 파라미터를 직접 미는 유일한 결정적 레버. 각과 분위기의 맞교환(가라 −1·행복 −1) | 코드 확정 + LLM 소견 |
| 공지 | 텍스트가 세계를 바꾸는 자리 — 원문이 활성 지침으로 모든 사건 생성에 주입되고, 방향 판정(N)이 파라미터를 민다. 점검과 달리 **결과가 문장의 질에 달렸다** | LLM 방향 → 코드 폭 |

셋의 관계: 점검은 확실하지만 방향이 고정, 공지는 자유롭지만 판정을 거치고, 상담은 부대가 아니라
사람을 고친다. 전부 같은 화폐(평판)를 쓰므로 「오늘 무엇을 돌보느냐」가 매일의 선택이 된다.

### 3.6 연출 (0콜 원칙)

| 요소 | 의의 | 결정 |
|---|---|---|
| 병영 소음(A) | 무대가 조용하면 부대가 죽어 보인다. 부임 때 한 콜로 100일치 — **아무 상태도 안 보기 때문에** 캐시가 거짓말이 안 된다 | 텍스트(캐시) |
| 군가 | 고증의 소리. 가사는 units.js의 static 인용(저작권상 한 소절) — LLM은 가사를 절대 안 쓴다. 도착 방식(목/방송)이 부대를 가른다 | static 텍스트 |
| 무대·해·통근 | 시간의 얼굴. 게임 상태는 슬롯 시각과 장소만 안다 | 코드 |
| 연출 난수 분리 | 말풍선 개수가 사고 확률을 밀면 안 된다 — 난수 통이 둘이다 | 코드 |

### 3.7 판정이 「방향만」인 이유 (요약)

E-3·N이 `up/down/same`만 내보내는 것은 이 게임의 가장 중요한 설계다.
폭까지 맡기면 (1) 밸런싱이 프롬프트 튜닝이 되고, (2) 모형이 후하게 주는 쪽으로 표류하고,
(3) 회귀 테스트가 불가능해진다. 방향은 판단이고 폭은 규칙이다 — 심판은 판단만 한다.

## 4. 이번 전환에서 일부러 안 한 것

- **멘탈의 LLM 판정화** — "면담 대화가 좋았으면 +2" 같은 것. 채점 금지 원칙(주임원사가 쓴
  글은 채점되지 않는다) 위반이고, 잘 쓴 질문 놀이가 되어 버린다. 회복은 +1 고정이다.
- **병사별 스탯 증식** — 체력·충성심·피로도… 멘탈 하나로 끝. 늘어나는 순간 관리 게임이
  스프레드시트가 된다.
- **계기판의 예측 표시** — "내일 행복도 −1 예정" 같은 것. 드리프트 공식을 화면에 다 풀면
  브리핑의 서사가 완전히 죽는다. 현재값까지만 보여준다.
